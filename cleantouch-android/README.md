# CleanTouch Android 0.3.4

앱 안의 원형 버튼을 ON 하면 다른 앱 화면을 무음 녹화하고, OFF 하면 저장된 전체 녹화 구간의 상품 분석을 자동으로 시작합니다. 플로팅 창과 SYSTEM_ALERT_WINDOW 권한은 없습니다.

## 사용 순서

1. 원형 OFF 버튼을 누르고 녹화·장면 전송 안내와 Android 화면 공유 창을 확인합니다.
2. ON 상태에서 다른 앱으로 이동해 평소처럼 봅니다. 정해진 10초 제한은 없습니다.
3. CleanTouch로 돌아와 ON 버튼을 누릅니다. 알림의 **종료하고 분석**으로도 종료할 수 있습니다.
4. 앱 화면이 자동으로 분석 진행 화면으로 바뀌고, 인식한 모든 상품 후보를 사진·등장 시점·검색 링크로 표시합니다.
5. 앱이 닫혀 있으면 분석 완료 알림을 눌러 결과를 봅니다. 백그라운드에서 결과 창을 강제로 띄우지 않습니다.

## 구현과 한계

- MediaProjection + MediaRecorder: 최대 긴 변 1280px, H.264, 24fps, 무음 MP4.
- 녹화 도중에는 촬영에 집중하고 OFF 후 분석합니다. 새 녹화는 최소 5초 간격으로 최대 24장면과 마지막 장면을 분석합니다. 이미 분석을 시작한 녹화는 기존 장면 시점을 유지합니다. 짧게 등장하거나 가려진 상품은 누락될 수 있습니다.
- Groq/Gemini가 한 장면의 여러 상품을 구분합니다. 상품별 영역 사진과 검색 경로를 유지하고, 동일한 검색 경로는 중복 제거합니다.
- 네이버와 Google 링크는 AI 설명으로 만든 **쇼핑 검색 링크**입니다. 동일 상품 확정, 실시간 가격, 재고를 보장하지 않습니다.
- 결과의 **상품 사진을 공유해 이미지로 찾기**를 누르면 잘라낸 상품 사진을 Android 공유 화면으로 보내 Google Lens 등 이미지 검색 앱에서 비슷한 이미지를 찾을 수 있습니다. 서버에 Cloud Vision이 설정되면 일치 이미지가 있는 웹페이지를 문자 검색보다 먼저 표시합니다.
- 순차 요청과 요청 간 최소 2.1초 간격으로 기본 분당 30회 제한을 고려합니다. 긴 녹화는 분석도 오래 걸립니다.
- 서버 오류·한도 초과·분석 중지 시 이미 완료한 결과와 원본 녹화를 저장하고 이어서 분석할 수 있습니다.
- 분당 AI 처리량 제한은 서버가 안내한 시간만큼 기다린 후 같은 장면을 자동 재시도합니다. 2분 이하 대기에 한해 장면당 최대 2회 재시도하며, 대기 중에는 카운트다운과 완료 장면 수를 표시합니다.
- Gemini의 일시적인 서버 과부하는 검색 서버에서 한 번만 재시도합니다. 계속 실패하면 명확한 오류와 함께 분석을 멈추고, 완료 결과와 녹화를 보존해 나중에 이어서 분석할 수 있습니다. 503 응답의 재시도 시각도 저장합니다. Gemini 응답 대기 시간은 최대 90초이며, 서버 응답 지연을 와이파이 연결 오류와 구분해 안내합니다.
- 일일 제한·긴 대기·반복 실패는 녹화를 보존하고 수동 재개로 전환합니다. 재시도 가능 시각을 저장해 앱을 다시 열어도 대기를 유지합니다. `2/78`은 전체 78장면 중 2장면을 처리했다는 뜻이며 상품 수와 다릅니다.
- 결과와 진행 상태는 앱 전용 저장소에 보존됩니다. 정상 분석 완료 시 해당 원본 MP4만 삭제합니다. 상품 사진과 결과는 남습니다.
- 사용자 종료 외에도 시스템 화면 공유 종료/잠금, 녹화 용량 한도(최대 2GB), 저장 공간 부족으로 녹화가 끝날 수 있습니다.
- 적응형 앱 아이콘과 단색 알림 아이콘은 전용 별/스캔 문양입니다. Android의 화면 공유 표시·동의창은 시스템이 관리합니다.

## 개발과 설치

JDK 17, Android SDK 36을 사용합니다. 이 PC의 도구는 프로젝트의 .local/android-toolchain 안에 있습니다.

휴대폰용 개발 APK는 PC와 같은 와이파이에서 접근 가능한 API 주소로 빌드해야 합니다. 기본값 10.0.2.2는 에뮬레이터 전용입니다.

~~~powershell
cd cleantouch-android
.\gradlew.bat assembleDebug -PCLEANTOUCH_DEBUG_API_URL=http://192.168.100.103:8790
.\gradlew.bat testDebugUnitTest lintDebug -PCLEANTOUCH_DEBUG_API_URL=http://192.168.100.103:8790
~~~

출력: app/build/outputs/apk/debug/app-debug.apk. 기존 debug 앱 위에 업데이트 설치할 수 있습니다.
PC IP가 바뀌면 주소를 바꾸어 다시 빌드합니다. 운영용은 HTTPS API 주소와 정식 서명이 필요합니다.

검색 서버는 프로젝트 루트에서 npm.cmd run dev:cleantouch-search로 실행합니다. 서버 인증키는 휴대폰에 넣지 않습니다.
APK 제공 서버는 scripts/serve-cleantouch-apk.mjs를 사용합니다. QR은 같은 와이파이의 다운로드 주소를 가리킵니다.

## 최근 검증 (2026-09-28)

단위 테스트·린트·개발 APK 빌드가 통과했습니다. 0.3.3은 새 녹화의 분석 대상 장면을 최대 24개로 제한하고, Gemini 503 응답의 재시도 시각을 저장합니다. 0.3.2의 응답 대기 시간과 연결 오류 안내도 유지합니다. 최소 지원 API 26에서 사용할 수 없는 화면 스타일 속성은 API 27 이상 리소스로 분리했습니다. 린트 권고 경고는 남아 있습니다.

이전 Groq 테스트에서는 분당 처리량 제한(429)과 30초 재시도 안내를 받은 뒤 테스트 이미지의 HTTP 200 및 상품 후보 2개를 확인했습니다. Gemini 키 인증과 모델 목록 조회는 성공했지만, 실제 Gemini 이미지 분석은 HTTP 503으로 아직 검증되지 않았습니다. 검색 서버를 재시작해야 `.env`의 Gemini 설정이 적용됩니다. 사용자의 78장면 전체 완료와 새 APK의 실기기 검증은 아직 완료되지 않았으며, 자세한 기록은 `PRODUCTION-CHECKLIST.md`와 루트 `HANDOFF.md`를 참고합니다.
