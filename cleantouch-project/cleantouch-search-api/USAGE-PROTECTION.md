# 요청 인증·공통 사용량 보호

Windows 0.1.64는 앱의 메인 프로세스에서 Ed25519 기기 키를 생성하고 Windows 보안 저장소로 암호화한다. AI 요청 본문, 고정 작업 경로, 시각과 난수를 서명한다. 서버는 공개키와 서명을 검증하고, 60초보다 오래된 시각·본문 변조를 거절한다. 기기 식별자는 공개키 지문이다. 키는 렌더러나 운영자 API 키와 공유하지 않는다.

**이 방식은 설치 기기 인증이며 회원 로그인이나 사람의 신원 인증이 아니다.** 재설치/키 재발급으로 다른 기기가 될 수 있다. 그래서 플랫폼이 제공한 연결 IP의 HMAC별 한도와 서비스 전체 한도를 함께 적용한다. 익명 클라이언트가 아예 새 키를 만드는 것까지 막는 앱 무결성 검증·고객 계정/조직 권한은 별도 과제다.

`db/usage.sql`과 동일한 `db/migrations/20261016010000_usage_guard/migration.sql`을 Netlify의 정식 마이그레이션 경로로 적용한다. `netlify.toml`의 `database.migrations.path`가 실제 빌드 경로다. 일반 실행 자격증명에 스키마 생성 권한을 부여하지 않는다. 서버 함수는 데이터베이스의 `ct_admit_request`를 호출한다. 날짜별 공통 행 잠금과 한 트랜잭션으로 전체·기기·네트워크·분당 한도를 검사하고 차감한다. 요청 난수도 같은 트랜잭션에서 기록해 여러 서버의 재전송을 거절한다.

처음 설정은 기존 Netlify 로그인으로 데이터베이스를 만들고 마이그레이션을 배포한 뒤 `scripts/provision-usage-store.cjs --configure`를 사용한다. 스크립트에는 Netlify CLI 모듈 경로 환경변수 `NETLIFY_CLI_MODULE_ROOT`가 필요하다. 서버 비밀값과 연결 문자열을 출력하지 않는다. 기존 HMAC 비밀값은 회전하지 않는다.

Netlify 무료 계정에서 세부 functions 범위 설정은 거절되어 현재 허용되는 전체 범위를 사용했다. 이 프로젝트의 빌드는 서버 TypeScript 컴파일이며, 변수 값을 공개 HTML·앱·클라이언트 코드에 넣지 않는다. 서버 관리 권한이 있는 구성원은 값을 읽을 수 있으므로 운영 팀의 권한도 관리해야 한다. 별도 HMAC 비밀값과 `USAGE_DATABASE_URL`은 서버 환경변수에만 둔다. 후자는 배포마다 분기된 DB로 이용량이 초기화되지 않도록 공통 운영 원장을 가리킨다. Netlify 레거시 함수에서 자동 DB 바인딩이 없을 때도 명시적 연결을 사용한다. HTTP 드라이버로 접근하며 인증서 검증을 해제하지 않는다.

`USAGE_GUARD_MODE=required`에서 저장소 장애·비밀값 누락 시 AI 공급자를 호출하지 않는다. `AI_PAUSED=true`는 AI 요청을 멈춘다. 환경변수 변경은 새 배포 후 확인한다. 구버전은 기본적으로 제한된 네트워크별 legacy 버킷을 사용하며, `AI_REQUIRE_SIGNED_REQUESTS=true`로 서명 없는 요청을 차단할 수 있다. Android가 서명을 지원하기 전에는 호환성을 확인해야 한다. 잘못된 서명이 있으면 legacy로 우회하지 않는다.

호스팅 JSON 함수는 기본 required다. 로컬 Express/Docker는 동일한 보호 모듈을 사용하며 공개 운영 시 required로 설정해야 한다. Express는 요청의 원문 JSON을 서명 대상으로 보존하고 클라이언트가 보낸 플랫폼 IP 헤더를 믿지 않는다. multipart `/v1/scans`는 서명하지 않는 기존 네트워크 버킷으로 제한하며, 서명 필수 모드에서는 이 경로를 거절한다. JSON 서명을 multipart 이미지 바이트의 인증으로 간주하지 않는다.

단위는 product/speech 2, chat 3, objects 5, similar 8, live-token 25다. 전체 기본 1,000/일, 기기 300/일, legacy 100/일, 네트워크 600/일 및 100/분이다. 실패도 예약분을 돌려주지 않는다. 이것은 실제 청구 금액이 아니라 보수적인 **요청 이용량**이다. 내부 다중 모델 호출, 이미지 크기, 토큰, Live 연결 시간의 실제 청구액을 미터링한 것이 아니다. 특히 클라이언트에 발급한 Live 토큰만으로 세션 지출을 강제 제한할 수 없다. 결제 활성화 전 공급자 수준 한도·청구 계측과 필요시 서버 중계가 추가되어야 한다.

데이터베이스에는 조회 문자열·상품 사진·음성·대화·원문 IP를 저장하지 않는다. 기기/네트워크의 가명 식별자와 이용량은 최대 7일, 재전송 방지용 해시는 3분 보존하며 후속 요청에서 만료 자료를 정리한다. 중단된 서비스의 잔존 자료는 다음 실행 전까지 남을 수 있으므로 엄격한 보존 기한이 필요하면 예약 정리가 필요하다.

로컬 검증은 운영 DB를 받지 않는 `scripts/test-usage-postgres.mjs`로 동시 30개 중 한도가 허용한 10개만 차감되는지, 재전송과 거절 시 중복 차감이 없는지 확인한다. 운영 적용은 별도로 실제 배포 요청을 확인해야 한다.
